#### Summary
- TCP 프로토콜에서 서버측 최적화와 단말측 최적화의 구조적 비대칭성 조사: 서버는 통제된 환경(BBR, MPTCP 등)에서 최적화 가능하나 단말은 OS가 의도적으로 보수적 파라미터 유지
- netem 기반 실험 환경에서 20ms/40ms RTT 측정 불일치 문제를 pcap 캡처 시점 및 egress qdisc 특성으로 규명
- idle 이후 cwnd 재시작 시 probe RTT를 이용해 baseline 대비 변화를 관측하여 cwnd 유지/리셋을 결정하는 delay-based 아이디어를 TCP Vegas/FAST TCP/Copa/BBR RTprop 등 선례와 비교 분석
- 손실 시 cwnd를 "절반"으로 줄이는 이유(Chiu-Jain 공정성 수렴 증명)와 idle 후 재시작 로직(Linux `tcp_cwnd_restart`의 RTO 경과 기반 지수감쇠)을 커널 코드 레벨로 분석 — LLM idle 시간이 RTO 대비 압도적으로 길어 감쇠 함수가 무의미해지는 지점을 규명
- baseline RTT 초과 비율(%) 기반 감쇠 알고리즘 제안: `decay_factor = clamp(1 - excess_ratio, floor=IW/cwnd, 1)`, excess는 RTO 공식(SRTT+4×RTTVAR)과 동일한 통계적 게이트 재사용
- Linux 커널 소스(tcp_input.c, tcp.h) 직접 확인: 실제 RTO 계산은 `SRTT + RTTVAR`(4배 아님, 스케일링에 흡수), RTTVAR 초기값이 200ms 최소 하한 보장 → "200ms + RTT"라는 세간의 표현의 실체 규명
- 커널의 RTTVAR은 EWMA 근사치(평균 절대편차)로 원본 RTT 샘플을 보존하지 않음을 확인 — 프로젝트 자체 probe.py가 원본 RTT 샘플을 보존 중이므로 이를 이용한 직접 표준편차 계산이 커널 rttvar_us보다 정확함을 실측으로 검증

#### Decisions
- idle 후 cwnd 재시작 로직에 "baseline RTT 대비 초과 비율(%) 기반 연속적 감쇠" 알고리즘을 채택 방향으로 구체화 (RFC2861의 경과시간 기반 감쇠를 실측 RTT 정보 기반으로 대체)
- RTT variation 판단 시 커널의 rttvar_us(손실 있는 EWMA 근사치)를 재사용하지 않고, 프로젝트 자체 probe 샘플의 원본 RTT 리스트로 직접 표준편차를 계산하는 방향으로 결정
- 이 로직은 "idle 복구 시점의 1회성 초기값 설정"으로 범위를 한정 — 상시 경쟁 구간에서 delay-based 알고리즘이 loss-based에 밀리는 구조적 약점을 회피
