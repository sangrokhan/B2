#### Summary
- 이전 세션(17:57)에 이어 "AI 서비스/토큰 전송 네트워크 대전환 연구" 주제를 구체화하는 대화 진행
- 1차: 사용자 체감 성능 / 신규 토큰 서비스 / 네트워크 운영 3개 축으로 넓게 후보 제시 (ITL jitter, HTTP/3, RTO floor, application-hint 소켓, 토큰 단위 QoS, KV-cache aware 라우팅, N:1 incast 재정의, IW10 재조정, ROI 모델 등)
- 2차 (Sangrok 피드백: "회사 비즈니스 이득 + 무선 단말 수준에서 이득 되는 기술"): 유선/서버 사이드 관점에서 무선 구간(RAN) 상태 전이 비용으로 축 전환. RRC Idle↔Connected 전환이 LLM idle 패턴과 충돌해 RRC 재수립(수백ms) + TCP cwnd reset이 이중으로 겹치는 문제를 핵심 포인트로 제시
- 3차 (Sangrok 피드백: "네트워크 장비 벤더 입장, RAN/코어 장비를 통신사에 납품"): 통신사가 구매할 이유가 되는 제품 차별화 기능으로 범위 최종 확정
- 최종 4개 연구 후보 도출: ① gNB(기지국) AI-aware RRC Inactivity Timer 동적 조정 ② UPF(코어망) LLM/SSE 트래픽 시그니처 자동 탐지→QoS Flow(5QI) 매핑 ③ 코어망 시그널링 — 단말→네트워크 "AI 세션 힌트" 프로토콜 확장(장기, 표준화/특허) ④ RAN 에뮬레이터(srsRAN/OAI) 기반 UE 단위 A/B 벤치마크·PoC 설계
- 기존 AIPT QUIC idle-probe 실측 결과(3g 프로파일 RTT 11~19% 악화 사전 감지)를 UPF 트래픽 시그니처 탐지 기능(②)의 기술적 토대로 연결
- Sangrok 요청으로 Obsidian(B2 vault) `~/wiki/연구/` 로컬 위키와 별도로, B2 topic-doc(`Knowledge/Dev/TCP 프로토콜 연구.md`)에도 이번 스코핑 결과를 챕터로 반영
